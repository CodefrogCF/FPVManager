# v0.5.0: Flutter test timeout follow-up

This is a **test-only** patch on top of `FPVManager_v0.5.0_followup_testfix_source.zip`.
No runtime code, data sources, database schema or application timeouts change.

## Changes

- `test/core/database/local_data_persistence_test.dart`: a two-minute timeout
  *only* for the file-backed, cross-repository SQLite reopen integration test.
  The 30-second default can be exceeded when Windows antivirus/file-system
  contention and concurrent test isolates are active.
- `test/features/spots/spot_filter_test.dart`: a two-minute timeout *only* for
  the large fixture test creating 10,000 SQLite spots + 10,000 tag rows. The
  measured query times still print separately; the longer test budget does not
  change production performance thresholds.
- `test/features/globe/map_layers_sheet_test.dart`: run explicitly awaited
  mocked provider/bridge requests via `WidgetTester.runAsync`, outside the
  widget test fake clock. Bound each to 20 seconds, so genuine stalls produce
  a targeted failure rather than the 10-minute widget watchdog.

## Run in PowerShell

```powershell
dart format test
flutter analyze --no-pub
flutter test --concurrency=1 test/core/database/local_data_persistence_test.dart --reporter expanded
flutter test --concurrency=1 test/features/spots/spot_filter_test.dart --reporter expanded
flutter test --concurrency=1 test/features/globe/map_layers_sheet_test.dart --reporter expanded
flutter test --concurrency=2 --reporter expanded
node --test test/js/*.test.cjs
```

If the map-layer test still times out with a 20-second timeout, report the
new failing line/stack. A genuine pending bridge acknowledgement or provider
operation must be debugged; do **not** further increase its timeout.

If file-backed tests still exceed two minutes when run individually, collect
fixture setup/teardown duration, database file locking and Windows Defender
activity. They are *functional* tests, not 30-second performance contracts.

## Environment and verification

This environment has no Flutter/Dart SDK, so these Flutter changes have not
been compiled or executed here. The existing successful Windows results are
`flutter analyze: No issues found` prior to the patch and 56 passing JS tests.
